## Disabled state

Use the native `disabled` attribute to prevent activation.

<Canvas of={ButtonStories.Disabled} sourceState="shown" />

Unlike `disabled`, `aria-disabled="true"` does not automatically prevent activation.

## Loading state

Combine a visual indicator with the appropriate HTML state.

<Canvas of={ButtonStories.Loading} sourceState="shown" />

The `loading loading-spinner` classes provide the visual indicator. Consumers manage asynchronous state, functional disabling, and accessible status updates.

`aria-busy="true"` communicates processing but does not disable the button.

## Icons and links

Compose buttons with icons, or style links for navigation.

<Canvas of={ButtonStories.IconsAndLinks} sourceState="shown" />

Decorative icons should use `aria-hidden="true"`. Icon-only buttons require an accessible name.

Use `<button>` for actions and `<a>` for navigation. Styled links retain their native link semantics.

## Light and dark themes

Apply `data-theme="light"` or `data-theme="dark"`.

<Canvas of={ButtonStories.Themes} sourceState="shown" />

Explicit theme selection takes precedence over the system color preference.

## Customization

Override public tokens or use compatible Tailwind utilities.

### Public CSS tokens

Customize colors and geometry through public `--aui-*` variables.

<Canvas of={ButtonStories.TokenCustomization} sourceState="shown" />

Internal `--_aui-btn-*` variables are not part of the public customization API. Preserve accessible contrast when changing colors.

### Tailwind utilities

Override supported presentation properties using Tailwind CSS utilities.

<Canvas of={ButtonStories.UtilityCustomization} sourceState="shown" />

Supported utilities take precedence through the documented CSS cascade without routine use of `!important`.
